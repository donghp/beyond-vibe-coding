**Purpose:** Partial failure, time, ordering, consistency, replication, partitioning, consensus, coordination, and fault tolerance.

## Guiding question
What changes when components communicate over a network and can fail independently?

## Prerequisites
Networking, databases, and concurrency.

## Suggested research path
Failure models → time and ordering → replication → consistency → consensus → distributed transactions.

## Engineering lens
Make trade-offs around availability, consistency, recovery, and operations explicit.

## Research rules
- Begin with an explicit and answerable question.
- Explain intuition before technical detail, without changing the underlying science.
- Use authoritative sources and cite claims close to their use.
- Separate evidence, interpretation, and illustrative examples.
- Include experiments only when they can be described and reproduced honestly.
- State assumptions, trade-offs, and limits.
