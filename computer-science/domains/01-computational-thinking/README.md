# Computational Thinking

**Purpose:** Problem decomposition, abstraction, representation, algorithms, correctness, complexity, recursion, and invariants.

## Guiding question
How do we turn a real problem into a computable model? How do we know an algorithm is correct? How does input size change resource requirements?

## Prerequisites
Basic programming and mathematical reasoning.

## Suggested research path
Computational models → problem decomposition → correctness → asymptotic analysis → complexity limits.

## Engineering lens
Translate ambiguous requirements into precise, testable computational tasks.

## Research rules
- Begin with an explicit and answerable question.
- Explain intuition before technical detail, without changing the underlying science.
- Use authoritative sources and cite claims close to their use.
- Separate evidence, interpretation, and illustrative examples.
- Include experiments only when they can be described and reproduced honestly.
- State assumptions, trade-offs, and limits.
