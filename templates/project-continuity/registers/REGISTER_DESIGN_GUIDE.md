# Project Register Design Guide

Do not create every register for every project. Select registers based on the project's domain, lifecycle, risk and operational needs.

Examples: prompt register (AI-assisted software), equipment register (energy projects), financial assumptions register (investment models), manuscript/chapter register (publishing), release register (software products).

Each register should state: owner, purpose, identifier policy, lifecycle/status semantics, authoritative source, update trigger, evidence references, and whether records are proposals or accepted. Avoid duplicating canonical records such as Product Definition or Decision Register.
