## Instructions for a new AI session

You are joining an existing project. Do not rely on a previous chat transcript or AI memory. Reconstruct the current project context from its canonical repository records.

1. Confirm repository identity, default branch, and live main/default-branch SHA.
2. Read BVC Global Continuity Bootstrap and Protocol.
3. Read this project's `PROJECT_CONTINUITY_PROFILE.yaml`.
4. Read the current Project State and Source Manifest.
5. Read the canonical sources named as mandatory in the manifest.
6. Inspect open PRs, branches, reviews and checks. Treat unmerged work as proposals only.
7. Reconcile the latest handoff against live sources.
8. Check external systems and local workspace status; mark unavailable facts UNKNOWN.
9. Classify facts as VERIFIED_FACT, OWNER_REPORTED, PROPOSAL, ASSUMPTION, UNKNOWN, or STALE.
10. Report the recovered state and one next action that is actually authorized.

## Authority rule

Current approved Human Owner decisions and canonical project records control. Project State and handoffs are navigation/snapshot aids. Open PRs are proposals. Chat history and AI memory are not durable authority.

## Before executing

- Confirm the current approved Task Contract or explicit authorization.
- Confirm exact CREATE/MODIFY/DELETE paths and budget.
- Check dependencies, baseline, recovery point and local state.
- Stop on authority conflict, scope expansion, missing evidence, or unverified preconditions.
- Keep human approval gates intact.

## Recovered-state report

Record: current branch/SHA, project baseline, lifecycle/milestone, active tasks/contracts, open decisions, risks, evidence, external-system status, local sync status, continuity health, and next permitted action.
