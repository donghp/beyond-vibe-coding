## 1. Executive Summary

Task #0026 delivers the **Carbon Regulatory Workspace** (`/carbon/ui/pages/regulatory-check.js`), exposing the statutory compliance, temporal boundary, sector taxonomy bridge, multi-ministry jurisdictional conflict, and controlled issues workflow through an enterprise-grade UI.

In strict accordance with the **G5 Regulatory Workspace Authority Constitution**:
1. **The UI is NOT a regulatory authority**: The UI layer does not perform, derive, or redefine statutory applicability, legal precedence, threshold evaluations, or emission math.
2. **Deterministic Consumption**: The UI consumes the immutable `RegulatoryViewModel` generated by `StateStore.getRegulatoryViewModel()`, which directly queries the G3 `RegulatoryEngine`, `TemporalEngine`, and `MethodologyEngine`.
3. **Fail-Closed Presentation**: Uncertain or conflicting legal jurisdictions (e.g. MONRE Circular 17/2022 vs MOC Circular 13/2024 for dual-use cement facilities) are explicitly flagged as `BLOCKED` or `REQUIRES_REVIEW` with full legal provenance.
4. **Controlled Issues Ledger & Auditor Disclosures**: Fully surfaces `ISSUE-RRM-001`, `ISSUE-TEMP-001`, `ISSUE-TEMP-002`, and provides an interactive, auditable disclosure filing system that persists into state with human verifier attribution.

## 2. Governed Information Architecture

The Regulatory Workspace is organized into 6 strictly governed panels:

```
+---------------------------------------------------------------------------------------------------+
|  REGULATORY WORKSPACE HEADER: Active Facility Selector, Reporting Period, Global Statutory Context |
+---------------------------------------------------------------------------------------------------+
|  1. EXECUTIVE STATUTORY APPLICABILITY CARD                                                        |
|     - Facility Identification (Legal Name, Tax ID, Province, Internal Sector ID)                  |
|     - Discrete Applicability Status (MANDATORY, APPLICABLE, NOT_APPLICABLE, REQUIRES_REVIEW)      |
|     - Statutory Mandate Indicator (Separate Boolean Dimension from Applicability)                 |
|     - Statutory Citation (Decision 42/2026/QĐ-TTg, Decree 06/2022/NĐ-CP)                          |
+---------------------------------------------------------------------------------------------------+
|  2. SECTOR CLASSIFICATION & TAXONOMY BRIDGE                                                        |
|     - Internal Sector vs Statutory National Code (e.g. Sector_1_MOIT vs SEC-01-ENERGY)           |
|     - Sector Mapping State: EXACT, MAPPED, PARTIAL, AMBIGUOUS, NOT_MAPPED, UNKNOWN               |
|     - Methodology Implication (Circular 38/2023/TT-BCT, Tier Default, Status)                     |
+---------------------------------------------------------------------------------------------------+
|  3. TEMPORAL BOUNDARY STUDIO (Decision 42 Transition: 2026-09-25)                                 |
|     - Boundary Timeline: Pre-Transition (Decree 06) -> Transition -> Post-Transition (Decree 83)  |
|     - Segmentation Control Toggle: Switch between single unsegmented vs dual compliant segments   |
|     - Temporal Compliance Status: SEGMENTED_COMPLIANT vs UNSEGMENTED_STRADDLE (Blocked)           |
+---------------------------------------------------------------------------------------------------+
|  4. JURISDICTIONAL PRECEDENCE CONFLICT ANALYSIS                                                   |
|     - Active Conflicts Banner: Flagging MOC vs MONRE guideline collisions (ISSUE-RRM-001)         |
|     - Governed Rule Evaluations: Detailed AST trace of statutory predicates evaluated by G3 engine|
+---------------------------------------------------------------------------------------------------+
|  5. GOVERNED CONTROLLED ISSUES LEDGER                                                             |
|     - Full inventory of open & disclosed regulatory issues (ISSUE-RRM-001, ISSUE-TEMP-001/002)    |
|     - Auditor Disclosure Filing Form (Scope, Description, Disclosed By, Timestamp)               |
+---------------------------------------------------------------------------------------------------+
|  6. STATUTORY COMPLIANCE MATRIX ACROSS REGISTERED FACILITIES                                      |
|     - Multi-facility summary grid showing compliance, sector code, and mandate status             |
+---------------------------------------------------------------------------------------------------+
```

## 3. Strict Prohibitions & Architectural Safeguards

| Forbidden Pattern | Safeguard & Implementation Result |
|---|---|
| Hard-coded regulatory math in UI | Verified zero formulas (`* EF`, `* 44/12`, `* 28`) in `regulatory-check.js` (TC-REGUI-016) |
| Hard-coded threshold checks in UI | Verified zero re-evaluations (`>= 25000`, `consumption > 1000`) in UI layer (TC-REGUI-017) |
| Merging applicability & mandate | Kept `status` (`APPLICABLE`) and `mandatory` (`boolean`) as separate dimensions (TC-REGUI-004) |
| Lossy state normalization | Displayed discrete statuses (`MANDATORY`, `REQUIRES_REVIEW`, `BLOCKED`, `UNKNOWN`) (TC-REGUI-003, 010, 011, 012) |
| State leakage between facilities | Verified multi-facility context isolation upon facility switching (TC-REGUI-018) |
| Unlabeled interactive controls | Form elements and selectors have explicit semantic labels and accessibility roles (TC-REGUI-020) |
