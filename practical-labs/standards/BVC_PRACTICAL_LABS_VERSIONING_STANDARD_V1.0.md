# BVC Practical Labs — Content Versioning Standard

**Document ID:** BVC-PL-VER-001  
**Version:** 1.0.0  
**Status:** Proposed common standard

## 1. Versioning

Use semantic versioning for lesson and standard content:
- MAJOR: learning outcome, task scope or instructional contract changes incompatibly.
- MINOR: new learning content, step, example or supporting section added compatibly.
- PATCH: corrections, broken links, typos or clarifications without changing the learning outcome.

## 2. Status

Use the readiness states in the Release and Review Standard:
DRAFT, EVIDENCE REQUIRED, READY FOR REVIEW, ACCEPTED, SUPERSEDED, WITHDRAWN.

Do not infer ACCEPTED from a merge event.

## 3. Change record

For each materially changed lesson record:
- Version.
- Date.
- Summary.
- Changed learning outcome or scope, if any.
- Evidence added or removed.
- Known limitations.
- Superseded version, when applicable.

## 4. Historical integrity

Do not silently rewrite historical evidence or remove accepted limitations. Prefer append-only evidence notes or a new version when the meaning materially changes.

## 5. Navigation

When a version is superseded:
- Link the previous version to the current version.
- Keep historical references resolvable.
- Update lesson indexes and registers.
- Clearly label archived versions.
