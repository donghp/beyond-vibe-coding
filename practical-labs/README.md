## Three complementary standards

- **Authoring Standard:** teaches authors how to create a useful, clear, verifiable lesson.
- **Project Instructions Standard:** teaches authors how to give an AI project-specific working rules.
- **Task Prompt Standard:** teaches authors how to prepare one bounded, checkable task.

The Project Instructions and Task Prompt standards do not grant authority or technically lock file access. The applicable Human Owner-approved scope remains controlling.

## Four learning phases

| Phase | Theme | Learning outcome |
|---|---|---|
| A | Meet AI & Build Your First App | Understand GAIS, create and inspect a blank app, establish Project Instructions, and communicate clearly with AI. |
| B | Build Your First Task | Create a title-only task, save it, reopen the app in the same browser profile, and verify persistence. |
| C | Make It Useful Every Day | Add My Day, My Tasks, Projects, Templates, Settings & Backup, and responsive everyday use progressively. |
| D | Beyond Beginner | Learn data, identity, security, source control, local development, testing, deployment, and maintenance. |

The full sequence and boundaries are in the [Curriculum Map v0.2.0](bvc-task-management/CURRICULUM_MAP_V0.2.md).

## How every lesson works

1. **Understand** — learn the practical outcome and why it matters.
2. **Inspect** — check the actual tool and project state.
3. **Prepare** — use complete context, a bounded prompt, and clear acceptance criteria.
4. **Authorize** — confirm the task is within the permitted scope.
5. **Execute** — perform one controlled task.
6. **Verify** — inspect the result and its evidence.
7. **Accept** — the learner / Human Owner decides whether the result is acceptable.

A write-capable prompt must pass the Prompt Readiness Gate before execution.

## Screenshot policy

Screenshots come from the actual tool session. Capture meaningful checkpoints, not every click.

Never include passwords, API keys, tokens, private account information, customer data, or other secrets.

An image slot or owner-supplied screenshot that has not been stored and linked in the repository must not be presented as a published lesson asset.

## Important learning boundaries

- Beginner lessons do not require Supabase, Auth, RLS, GitHub, VS Code, or Localhost as prerequisites.
- Intermediate and Advanced topics are introduced only when the learning path reaches them.
- A visible Preview is not proof of persistence, security, production readiness, or deployment.
- A successful AI response or build is not proof that the requested behavior works.
- The actual GAIS interface and generated project files must be observed. Do not invent button names, menu locations, file names, commands, versions, or build settings.
- Project Instructions guide AI behavior; they are not a technical sandbox or file permission boundary.
- The repository's approved product and architecture baselines remain authoritative. Practical Labs do not override them.

## Relationship to the book

The GitHub Practical Labs let readers experience the value of building with AI and learning by doing. The book **BEYOND VIBE CODING** provides the broader method: turning ideas into clear requirements, guiding AI through bounded steps, reviewing changes, verifying behavior, and keeping the human in control.
