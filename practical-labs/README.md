# BEYOND VIBE CODING — Practical Labs

**Build with AI. Learn by Doing.**\
**Dong Hong Style — Everyday Problems, Real Apps, Human Control.**

Welcome to the practical learning companion for **BEYOND VIBE CODING** by Dong Hong.

These labs help you move from an everyday problem to a useful application by working with an AI coding tool one small step at a time. You do not need to be a programmer to begin.

The first learning project is **BVC Task Management**: a simple daily work manager built progressively with Google AI Studio (GAIS).

> Start with one useful task. Learn one clear step at a time.

| A | Meet AI, Build Your First App | Understand GAIS, create a first blank web app, and learn to communicate with AI. |

## How every lesson works

1. **Understand** — learn what you are about to do and why it matters.
2. **Build** — perform one small action at a time with AI.
3. **See** — compare your screen with an authentic checkpoint screenshot.
4. **Prove** — check that the expected result actually happened.
5. **Continue** — move forward only after the checkpoint is understood.

A lesson must tell you what to click or type, why you are doing it, what you should see, how to check it, and what to do when the result differs.

## Screenshot policy

Screenshots are captured from the actual GAIS session used to produce the lesson. We do not take a screenshot of every click. We capture meaningful checkpoints.

Never include passwords, API keys, tokens, private account information, customer data, or other secrets in screenshots.

Image slots with `PLACEHOLDER` in their names are drafting aids. They must be replaced with authentic, privacy-safe screenshots before a lesson is marked ready for publication.

## Important learning boundaries

- Beginner lessons do not require Supabase, Auth, RLS, GitHub, VS Code, or localhost as prerequisites.
- Intermediate and Advanced topics are introduced only when the learning path reaches them.
- A visible Preview is not proof of persistence, security, production readiness, or deployment.
- A successful AI response is not proof that the requested behavior works. The learner must verify the result.
- The actual GAIS interface and generated project files must be observed. Do not invent button names, menu locations, file names, commands, or build settings.
- The repository's approved product and architecture baselines remain authoritative. These learning materials do not override them.

## Relationship to the book

The GitHub Practical Labs let readers experience the value of building with AI and learning by doing. The book **BEYOND VIBE CODING** provides the broader method: turning ideas into clear requirements, guiding AI through bounded steps, reviewing changes, verifying behavior, and keeping the human in control.
