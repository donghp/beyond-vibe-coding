# Practical Lab Review Checklist

## Learning experience
- [ ] One lesson, one practical outcome.
- [ ] Everyday problem is explained before technical terms.
- [ ] Genuine prerequisites only.
- [ ] One main action per numbered step.
- [ ] Expected visible result is described.
- [ ] Common mistakes and safe recovery are included.

## Prompt and execution safety
- [ ] Prompt package is complete where AI action is required.
- [ ] Source of truth is named.
- [ ] Current state is inspected or marked unknown.
- [ ] Authorized paths and operations are explicit.
- [ ] Forbidden changes and stop conditions are explicit.
- [ ] Acceptance and verification are checkable.
- [ ] Human retains acceptance authority.

## Evidence
- [ ] Evidence labels are correct.
- [ ] Screenshots come from the actual tool session.
- [ ] Image files exist on the target branch.
- [ ] Captions describe visible facts only.
- [ ] Secrets and private data are absent.
- [ ] Unverified behavior is not described as working.

## Editorial and repository
- [ ] Dong Hong Style is followed.
- [ ] Previous / Next / Index links work.
- [ ] Relative links resolve.
- [ ] Markdown / YAML / JSON are valid.
- [ ] Project decisions remain unchanged.
- [ ] Changes stay inside `practical-labs/`.
- [ ] PR describes validation and limitations.
