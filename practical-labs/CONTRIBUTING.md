# Contributing to BVC Practical Labs

Welcome. Practical Labs help readers learn by building something useful, one small step at a time.

Before creating or changing a lesson, read:

1. [Authorization and Scope](AUTHORIZATION_AND_SCOPE.md)
2. [Practical Labs Authoring Standard v0.2](standards/BVC_PRACTICAL_LABS_AUTHORING_STANDARD_V0.2.md)
3. [Dong Hong Style Guide](standards/DONG_HONG_STYLE_GUIDE_V1.0.md)
4. [Evidence and Screenshot Standard](standards/BVC_PRACTICAL_LABS_EVIDENCE_STANDARD_V1.0.md)
5. The relevant project's current curriculum and lesson status register.

## The contribution workflow

1. Identify the learner and one practical outcome.
2. Read the project's source of truth and current decisions.
3. Inspect existing lessons, prompts, assets and links before creating new ones.
4. Draft the lesson using the approved template.
5. Prepare complete prompt packages when AI is asked to inspect or change artifacts.
6. Check every UI instruction against authentic, current observations.
7. Add evidence labels and distinguish facts from inference.
8. Run the local/document checks available for the files changed.
9. Create a dedicated branch and submit a Pull Request.
10. Leave merge and acceptance authority with the Human Owner.

## Scope and authority

A lesson explains how to learn. It does not approve a product feature, architecture change, UX decision, security exception, implementation contract, or deployment.

Never change canonical project decisions or application code from a Practical Labs contribution unless a separate authorization explicitly covers that work.

## Evidence

Do not invent screenshots, UI controls, commands, file names, runtime outcomes or successful tests. A lesson may be drafted without every screenshot, but missing evidence must be labelled and must not be represented by a placeholder image that looks genuine.

Preserve owner-supplied originals. Any redacted, annotated or cropped derivative must be a separate asset.

## Pull Request checklist

- [ ] All changes stay within the authorized path.
- [ ] One lesson has one primary outcome.
- [ ] Current source-of-truth documents were checked.
- [ ] Prompt readiness and authorized scope are clear.
- [ ] Screenshots are authentic and privacy-safe.
- [ ] Evidence labels are accurate.
- [ ] Relative links resolve.
- [ ] Lesson navigation is correct.
- [ ] Project decisions and existing accepted boundaries are preserved.
- [ ] Validation results and remaining limitations are stated.
- [ ] No automatic merge is enabled.
