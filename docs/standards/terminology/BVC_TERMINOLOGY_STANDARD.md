# BVC TERMINOLOGY STANDARD V1.0

STATUS: CANONICAL VISUAL + AI SYSTEMS TERMINOLOGY AUTHORITY
VERSION: 1.0
GOVERNANCE: GLOBAL / PERMANENT

## 1. PURPOSE

The BVC Terminology Standard defines the canonical semantic meaning of all domain terms used in **BEYOND VIBE CODING — LIVING BOOK**.

It ensures that:
- The book's terminology is consistent across all chapters.
- AI systems and visual diagrams use the same semantic definitions.
- The reader has a stable, reliable reference for technical concepts.

## 2. CORE PRINCIPLES

### 2.1 One Term, One ID, One Meaning
Every concept in the BVC ecosystem must have a unique **Semantic ID** and a single **Canonical Definition**.

### 2.2 Semantic Authority
The Glossary is the authority. Other systems (Visual Engine, Search, UI) must consume definitions from the Glossary registry.

### 2.3 Source Provenance
Canonical definitions must be derived from the book's manuscript. No term can be promoted to "Canonical" status without evidence from the source material.

### 2.4 Zero Manuscript Rewrite
The Glossary system reads manuscripts for indexing but MUST NOT modify them.

## 3. TERM CATEGORIES

- **AI Systems Engineering**: Core concepts of building with AI.
- **Engineering Method**: Ways of working and processes.
- **Project State**: Concepts related to the current truth of a project.
- **Governance**: Constraints, permissions, and authorities.
- **Execution**: The act of performing work.
- **Verification**: Proof and validation of work.
- **Visual Semantics**: Visual roles and diagram components.

## 4. TERM LIFECYCLE

1. **PROPOSED**: Candidate term extracted from manuscript.
2. **REVIEWED**: Definition verified against source material.
3. **CANONICAL**: Approved for global use as authority.
4. **DEPRECATED**: No longer the preferred term.
5. **REJECTED**: Explicitly denied as canonical terminology.

## 5. VISUAL INTEGRATION

Every canonical term may map to a **Visual Semantic Role**. 
- `authority` -> Deep Blue
- `flow` -> Sky Blue
- `verification` -> Energy Green
- `warning` -> Amber
- `critical` -> Red

Visual components must reference the Term ID to determine their visual representation.

## 6. CHANGE CONTROL

Any change to a Canonical term requires an explicit version update to the Terminology Standard.
